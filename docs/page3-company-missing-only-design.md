# 公司介绍只补缺项

## 原因与设计
旧检查入口在公司介绍某处为空时，仍调用整套fillCompanyIntroTemplate；平台重新选模板会替换公司文案/图片，并可把FAQ重置为模板默认问答。恢复FAQ快照只能保护FAQ，不能保证已有公司文字和图片不变。

现在复用同一个平台模板应用回调companyInfo_template_useTemplate，仅在templateData中传入缺失字段。模板详情沿用该控件自己的只读getTemplateDetailUrl/commonPuck.get；不会保存、编辑或删除平台模板。原一键填入整套选择模板仍保留，检测补缺入口不再重新选择整套模板。

## 文件与流程
content/page3-review-company.js同时由manifest内容脚本及background importScripts加载。repair在独立世界检查当前商品、滚至公司卡片标题；后台repairCompanyTemplateMissing校验顶层商品页、商品/文档时间、行/文件/任务以及截止时间，再通过MAIN调用独立applyMain。

applyMain只读取scene=companyInfoTemplate的原控件；必须唯一、精确匹配原类目模板名称。复用pickCompanyIntroTemplate的strict选项：未知类目拒绝猜测，原一键填入的默认Polo行为不变。

从原getTemplateData读取当前值并克隆；图片组按value唯一匹配，已有非空组完全保留，只有全空组补入模板imageList，缺整组才新增；已有公司文字保留，只有空白文字才取模板文字。请求期间重新读取快照，用户改动则停止。调用原onChange时，patch根本不包含companyFaqDesc，避免再清空FAQ。回读验证已有组、非空文字及FAQ保持，只有缺失项改变。比较忽略对象键的插入顺序，仍严格比较字符串与数组内容/顺序，避免平台重构对象产生假报警。

模板读取有15秒截止及Promise.race超时；过期结果不得晚到补填，不重发。首次保存前尚无itemId时以任务/行/文件和文档时间绑定；有itemId后必须匹配。

## 优点和边界
不重新上传已有图片、不重选模板、不用模板默认FAQ替换原问答；继续使用平台自己的受控表单更新链，而非innerHTML或直接给内部model赋值。局部字段补缺不影响原整套填入入口。

只检查图片组是否有内容，不能证明已非空组中每张图片都与模板完全一致；不替换用户自定义非空图片或文字。平台控件/接口结构变化、来源不唯一、网络过期或回读异常时停止后续保存，不盲目选择第一个模板。回读异常不声称自动回滚平台异常，需核对当前内容。该适配依赖当前平台原控件回调，必须维护真实回归。
