# 保存后复查闭环控制器设计及实施进度
时间：Asia/Singapore UTC+08:00，详见文件名。
需求：保存当前商品后检查，仅补缺失项，重新保存复查，通过后再推进下一行；保留用户已有内容，保存未确认不得自动重发。不提交上架，不改Excel，不自行刷新或重载扩展，不提交推送。
发现：page3.js两处填完自动保存后都会publishFilled；background.js的onPublishFilled在当前任务/标签/行一致后直接remaining.shift，并不以保存后复查为条件。savePublishProduct自身会写保存记录并发publishSaved。因此仅在保存回调后增加检查不能防止页面重载及旧保存记录提前跳过。
计划：1 独立可测试状态控制器；2 接入跨页面存储及本次保存尝试证据；3 接原补缺器及后台完成闸门；4 真机单商品保存复查，不开批量，不提交。必须在步骤2/3完成后才能启用。
本批新增content/page3-save-review-cycle.js和tests/test-page3-save-review-cycle.js。独立状态ready/saving/reviewing/repairing/complete/blocked；保存前持久化，恢复saving要求相同attempt保存证据，缺失项有action才能补，unknown停止，默认最多两轮补缺；repairing中断不自动重放，商品身份在每次异步后重新确认，存储失败先于保存终止。
优点：分离平台交互和控制，便于原补缺器复用，避免整页重填及保存超时重复点击。能力边界：暂未加入manifest或接原入口，不改变当前扩展行为；没有真实持久存储、后台attempt证据、并发锁或队列闸门；complete只是控制器结论，不能单独推进队列。适配器必须串行运行并使用现有二次读数补缺保护。整体功能尚未完成。
专项通过：正常保存后全通过、重复complete无副作用、只修缺单位保留标题、两轮上限、未知停止、保存未确认停止、重载恢复不重发、旧attempt拒绝、商品切换拒绝、存储失败无保存、补缺中断拒绝重放、空结果/非法状态/无补缺入口拒绝。
