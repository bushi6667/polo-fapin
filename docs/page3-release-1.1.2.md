# 1.1.2：页3保存后复查与安全补缺

## 行为
一键填入后的自动保存使用同一闭环：保存成功并重载后检查实际内容；仅补明确空缺，再保存复查；通过后才允许队列完成当前商品。已有内容和自定义值保留，评分不触发整页重填。

最多两轮补缺（包括保存前补缺）。无法确认、缺少来源、保存未确认、身份变化或补缺失败时停止当前商品。首次保存前保留必填检查，避免平台直接拒绝保存。默认手动检查按钮只检查，不写入；独立保存按钮不启动新的自动闭环。

## 设计与范围
复用原上传/单项填入函数，补缺器二次读取后才写入。新增独立模块负责卖点提交、公司图片组/文字局部合并、颜色/尺码/模板补缺及保存状态恢复。公司介绍不覆盖已有文字、非空图片组和FAQ。修复箱规“仍要关联”识别与后续证据判断。

保存前持久记录尝试，重载后核对当前任务、文件、行、商品ID和保存尝试。最终重新质量检测后再检查实际内容，避免等待期间的空缺被旧结果放行。后台待复查记录阻止超时跳行和重复整页填入。

## 验证与边界
当前单商品的实际保存重载、自动恢复、最终全项复查与后台完成确认已通过。FAQ单项补缺再次保存、公司文字/图组缺失及自定义数据保留有真实验证。完整页面18个单项修复按钮均验证不重填。

真实跨商品连续队列仍未实测，供用户另一台电脑小批量验证。检查以是否填写为主，不证明非空内容语义正确；非空图片组内部少图不自动补。平台DOM或编辑器变化可能需要适配。保存超时不自动重发；关闭标签或丢失恢复进度不承诺自动续跑。

已知测试基线并非全绿：此前111文件98通过、12既有失败、1既有超时。发布前最终结果见本次时间记忆。更新后重新加载扩展并刷新商品页；只更新目录而不重载，旧页面不会使用新版内容脚本。
