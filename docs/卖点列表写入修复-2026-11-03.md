# 商品卖点列表写入修复

## 原因与证据
2026-11-03真实失败现场：卖点正文显示在普通div中，#textDesc .length为0/2000，占位提示仍在。平台TextAreaList的正文getter只读取ul li，普通DOM文字不会进入该表单值。聚焦空框时平台会初始化ul/li，Enter键处理器负责新增li；input处理有500ms节流。旧流程以根编辑区selectAll/delete清空后直接insertText换行，并在节流结束前仅比较每条前12字，无法证明正文被平台接收。
已确认的是列表结构和平台取值契约；本轮未逐命令重演旧实现的每个失败路径，不把调试器冲突说成唯一根因。测试页面调试器会与扩展realClick竞争，故实际验证没有附加商品页，而是连接本扩展后台，通过chrome.scripting读取和执行。

## 实现与优点
新增content/page3-highlights.js，保持平台生成的ul/li，逐条使用平台Enter行为建立列表项；空框不清空，显式覆盖仅选择当前列表项内部，禁止全局selectAll。完整比对正文和条数，读取卖点自身计数器（不读.next-input-len），等待节流并在失焦后复核。
page3.js保留原预解析优先、本地parseHighlights回退、CJK过滤和仅desc_en的数据规则，只将写入委托给新模块。手动检查的补缺调用传missingOnly，填写前后复查，用户期间填值则保留。page3-review.js不再仅凭innerText判卖点通过；保存前审查也要求列表与计数一致。manifest加入模块加载。

## 能力边界
不保存、不上架、不用批量模式、不改源数据、不恢复stash、不提交推送。不新增label、不改页1解析、不做追加去重。旧DOM有字但没有合法列表时报告无法确认，避免无授权覆盖用户内容；不通过私有React方法写状态。完整保存后服务器持久性未验证（禁止保存）。本修复不接手stash中箱规/颜色/尺码等未完成改动。
