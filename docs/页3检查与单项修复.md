# 页3检查与单项修复

## 原因
原入口同时检查整页并补缺，单项测试会带动其他空项填入，难以判断改动范围。

## 行为
默认“检查空缺（不填入）”只运行读取与必要区域呈现，不运行补填，也不主动点击质量检测。
选择项目后点击“仅修复所选项”，只检查该项、补该项空缺、再读取该项结果。
“修复整页空缺”作为明确的独立操作，沿用已有内容保留规则。
三种操作均不保存、不发布、不推进队列。

## 优点
可先看问题再指定修复，颜色/尺码测试不再连带补写卖点、FAQ或其他属性。底层readOnly阻断修复调用，单项在运行前过滤项目。

## 边界
呈现检测区域可能滚动页面并触发平台自身渲染；不代表写入表单。单项所需前置数据不足时报告未确认，不擅自补其他项。既有复杂控件适配缺口仍保留，界面分离不代表所有补缺功能已验证。

## 验证
readOnly专项已验证fail也不调用自带修复或回退填入；入口专项已验证所选action与整页模式分离。真实按钮零写入、单项不影响其他字段需加载新版后另行记录。
