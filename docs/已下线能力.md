# 已下线能力与原因

> 记录被移除的接口，避免以后重复踩坑。最后更新：2026-10-27

## 一、账号可用性判定：从「读额度百分比」改为「真实生成」

最早的做法是开账号菜单读「近 7 天消耗 N%」判断还能不能生成。**这个方法不可靠，已删。**

失败原因：

1. 菜单里的额度条目有**两种文案**，随账号状态切换：
   - 已用满的号：`近 7 天消耗消耗 100%`
   - 新号 / 未消耗：`当前时段额度用量 0%`
2. 百分比和「这一次能不能出图」不是一回事。100% 的号有时还能出图，0% 的号也可能因为别的限制被拒。
3. 用户明确说明：**生成额度每天刷新**，昨天的「没额度」对今天没有参考价值。

现行做法：不看百分比。当前号弹额度 → 切下一个号 → 直接重跑当前这一款 → 出图就继续、又弹额度就再换。

相关下线接口：`doubaoQuotaPercent`（消息动作）、`readQuotaPercent` / `parseDoubaoQuotaPercent` / `doubaoRawSnippet`（内容脚本函数）。

## 二、试生图探测：`doubaoProbeGenerate`

曾经做过一版「切到某个号，发一条『生成一张纯白背景的图片，1:1』看能不能出图」的探测，用来给账本标 ok。

**已删**，原因：

- 每探测一个号就真消耗 1 张额度，10 个号就是 10 张；
- 用户明确要求「不需要发其他，直接发当前要生成的图片就行」；
- 探测与生产合一之后，探测本身没有存在意义。

判定出图的口径（当年验证过，留档备查）：只认新增的、`src` 含 `byteimg.com` 或 `tos-alistore`、且 `naturalWidth > 0` 的 `img`，且**必须在消息节点内**找——整页扫描会把侧边栏会话缩略图和头像的延迟加载误判成出图。超时 90 秒，超时不算「没额度」。

## 三、全量扫描与独立选号：`doubaoScanAccounts` / `doubaoPickAccount`

曾经实现的「把每个号都切一遍、逐个探测、写账本」和「从账本里挑一个能用的号」两个独立动作。

**已删**，原因：没有任何发送方（页面、套图、popup 都不调用），实际自动换号走的是 `doubaoAutoSwitch`，它是「切到第一个候选就返回，由页面重跑真实任务来验证能不能用」。

如果想手工排查账本，用现存的 `doubaoGetAccountLedger` / `doubaoResetAccountLedger` 两个动作（无 UI 入口，控制台调用）。

## 四、账号账本的 `ok` 状态

账本（`chrome.storage.local` 的 `polo_doubao_accounts_v1`）结构里仍保留 `status: 'ok'`，但**现在没有任何代码会写入 ok**，实际只会出现：

- `exhausted`：这个号刚被额度拒（`note: quotaExhausted`）
- `unknown`：没测过、切号失败、需要登录、结论不明

`ok` 只是历史兼容值，排候选时排在最前面。`percent` / `label` / `resumeAt` 是诊断字段，当前无消费者。
